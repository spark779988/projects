## 2. 部署前检查

### 2.1 确认远程代码是最新版本

EdgeOne 会从 Git 仓库拉取代码，因此部署前必须保证 GitHub 的 `main` 分支包含完整网站文件。

本次提交并推送的命令：

```powershell
git add AGENTS.md assets/favicon.svg index.html script.js styles.css
git commit -m "feat: build personal homepage"
git push origin main
```

随后核对本地与远程 SHA：

```powershell
git rev-parse HEAD
git ls-remote origin refs/heads/main
```

两侧均为：

```text
92526714656cb4ad921ffe176f887286152d69d7
```

### 2.2 确认项目是纯静态站点

项目根目录直接包含：

```text
index.html
styles.css
script.js
assets/favicon.svg
```

项目没有 `package.json`、构建命令或构建产物，因此部署时不执行安装和构建，直接发布根目录。

## 3. 开通 EdgeOne Makers

1. 打开 EdgeOne Makers 控制台：<https://console.tencentcloud.com/edgeone/makers>
2. 进入“服务总览”，切换到“Makers”。
3. 首次使用时，页面显示“您好，欢迎使用 EdgeOne Makers”。
4. 点击“立即开通”。
5. 等待控制台刷新并出现“导入 Git 仓库”“从模板开始”“直接上传”等入口。

开通后不需要额外购买套餐即可创建当前免费项目。

## 4. 连接 GitHub

1. 在 Makers 首页点击“导入 Git 仓库”。
2. 在 Git 平台列表中选择 GitHub。
3. 浏览器跳转到 GitHub OAuth 授权页。
4. 授权页完成身份验证后，进入 EdgeOne Makers GitHub App 安装页。
5. 仓库访问范围选择“Only select repositories”。
6. 搜索并只选择 `spark779988/projects`。
7. 点击“Install”。
8. 返回 EdgeOne，等待 GitHub 仓库列表加载。
9. 选择 `projects` 仓库。

本次只授权了 `projects` 单个仓库，没有授予 EdgeOne 访问全部仓库的权限。

### GitHub 授权异常的处理

第一次打开 OAuth 页面时，按钮附近出现“您目前无法执行该操作”，原因是 GitHub 检测到多个标签页的登录会话发生切换。

处理方法：

1. 保持同一个 OAuth 地址。
2. 刷新页面以同步最新 GitHub 会话。
3. 重新进入 GitHub App 安装步骤。
4. 不绕过 GitHub 的禁用按钮或安全提示。

## 5. 创建项目

EdgeOne 读取仓库后进入“创建项目”配置页，填写如下：

| 配置项 | 本次值 | 说明 |
| --- | --- | --- |
| 项目名称 | `projects` | 与 GitHub 仓库名称一致 |
| 加速区域 | 全球可用区（不含中国大陆） | 免备案路线 |
| 生产分支 | `main` | 推送 `main` 后自动部署 |
| 框架预设 | `Other` | 原生静态项目 |
| 根目录 | `./` | 网站根文件位于仓库根目录 |
| 输出目录 | `./` | 直接发布 `index.html` 所在目录 |
| 构建命令 | 留空 | 不需要编译 |
| 安装命令 | 留空 | 没有第三方依赖 |

确认配置后点击“开始部署”。

## 8. 后续更新方式

本地修改网站后执行：

```powershell
git status
git diff
git add .
git commit -m "更新说明"
git push origin main
```

只要新提交推送到 GitHub 的 `main` 分支，EdgeOne 就会拉取最新提交并自动重新部署。

不建议使用 `git add .` 之前跳过 `git status` 和 `git diff`；先确认不会把临时截图、密钥或无关文件纳入提交。

## 9. 注意事项

1. 当前地址是 EdgeOne 预览域名，不是正式站点域名。
2. 中国大陆网络访问预览域名可能返回 `401`。
3. 正式公开访问需要进入第 7.3.2 节，绑定自定义域名并配置免费 HTTPS 证书。
4. 选择“中国大陆加速”时，自定义域名需要备案；当前全球可用区路线可以避开该要求。
5. GitHub 授权应保持最小仓库范围，不要把安装权限扩大到全部仓库。
6. 不要把 GitHub Token、腾讯云密钥或 OAuth 回调中的 `code` 写入项目文件或公开日志。
